# F5 — Practitioner Issues: macOS Desktop Lyrics (GitHub)

**Status**: success  
**Angle**: Real user problems & workarounds from GitHub issues on Lyrimuse, LyricsX, QQ Music-related lyric sources, and menu-bar lyrics apps.  
**Method**: `api.github.com/search/issues` + issues list/comments. Chinese queries: 桌面歌词 mac, 悬浮歌词, 菜单栏歌词, QQ音乐 桌面歌词.

---

## Summary (3–5 lines)

LyricsX is effectively abandoned; most open issues are display clipping on Sonoma/Sequoia, QQ/NetEase API breakage, Spotify track-switch lyric loss, and Sonoma crash with no menu-bar icon. Community forks (MxIris, WuBarlynn) and replacements (Lyric Fever, Lyrimuse) carry the load. Users repeatedly hit: unsigned-app quarantine, lyric-source API decay, dual-layer / truncated floating windows, and menu-bar space conflicts with hidden-bar managers. Workarounds are mostly “use a fork + priority Kugou + xattr quarantine strip,” not product fixes. Lyrimuse is the actively maintained alternative but still has intermittent menu-bar lyric disappearance and overlay UX friction.

## Top practitioner problems & workarounds

### 1. QQ Music lyric API dead — community rebuild required
- **Problem**: LyricsX can no longer fetch QQ Music lyrics; NetEase also often fails. 35+ comments; original search API expired.
- **Workaround**: Use Mx-Iris rebuilt zip / fork (`MxIris-LyricsX-Project`); strip quarantine with `sudo xattr -rd com.apple.quarantine /Applications/LyricsX.app`. Prefer Kugou source (most likely to scroll).
- **URL**: https://github.com/ddddxxx/LyricsX/issues/601

### 2. Search hangs / only first song after restart has lyrics
- **Problem**: Lyric search spinner forever; only the first track after app restart finds lyrics. Related to NetEase Set-Cookie `compactMap` publisher bug (fixed in LyricsKit 0.11.3 by jjaychen1e, community app zip).
- **Workaround**: Custom build from issue thread; rebuild; wait for fork. No stable official release.
- **URL**: https://github.com/ddddxxx/LyricsX/issues/577  
- **Related fix discussion**: https://github.com/ddddxxx/LyricsX/issues/581 (72 comments, NetEase cookie pipeline)

### 3. Sonoma crash + missing menu-bar logo
- **Problem**: LyricsX quits seconds after launch on macOS Sonoma (Apple Silicon); status-item never appears so users cannot open settings.
- **Workaround**: Homebrew cask install reported working by some; others stay on 1.6.3 or switch forks.
- **URL**: https://github.com/ddddxxx/LyricsX/issues/606

### 4. Floating/line lyrics truncated (Sequoia / macOS 15–26)
- **Problem**: Horizontal lyrics clipped mid-line; partial disappearance; M1 Pro Sequoia screenshots show cut-off text. Still open across #634, #636, #639, #642, #646.
- **Workaround**: MxIris v1.6.5+ “关闭候选字体”; WuBarlynn ARM fork claims fix for incomplete display.
- **URLs**:
  - https://github.com/ddddxxx/LyricsX/issues/634
  - https://github.com/ddddxxx/LyricsX/issues/636
  - https://github.com/ddddxxx/LyricsX/issues/639
  - https://github.com/ddddxxx/LyricsX/issues/642
  - https://github.com/ddddxxx/LyricsX/issues/646

### 5. Spotify: lyrics vanish on track switch; desync half-line
- **Problem**: Lyrics disappear on every Spotify song change until LyricsX restart; on newer macOS Spotify lyrics lag ~half line; offset write to `.lrcx` often ineffective.
- **Workaround**: Quit menu-bar “hidden” managers (user reported conflict); restart app; prefer Apple Music path.
- **URLs**:
  - https://github.com/ddddxxx/LyricsX/issues/587
  - https://github.com/ddddxxx/LyricsX/issues/617

### 11. Menu-bar space & conflicts (icons disappear / conflict with managers)
- **Problems**:
  - Long lyrics eat menu bar; “Nothing Playing” still occupies space (LyricFever #37).
  - Menu-bar hide managers (e.g. hiddenbar, Ice) conflict; status items leave blank gaps or fail to restore after sleep (MxIris fork blank strip; Ice Bar after wake).
  - Notch Macs: fixed menubar lyrics unfriendly; users want floating overlay instead (menubar-lyrics #1).
- **Workarounds**: Quit hide-manager; click app then Settings/Quit (LyricFever author); Ice wake fix PR; prefer floating window over menubar on notch.
- **URLs**:

### 12. Local `.lrc` priority / Spinsian / multi-player gaps
- **Problems**: Cannot prefer local same-path `.lrc` over network lyrics; “Load lyrics beside music file” only works for Apple Music (not Swinsian/Spotify); auto player-switch detection fails.
- **Workaround**: Manually set preferred player; enable precise search carefully (breaks traditional-Chinese Spotify titles → convert to simplified).

## Pattern takeaways for product/build decisions

| Pain | Cause | Community answer |
|------|--------|------------------|
| No lyrics / search forever | Lyric source APIs (QQ, NetEase) change or rate-limit | Multi-source + cookie-aware clients; prefer Kugou/LRCLIB |
| Clip / blank on new macOS | App unmaintained; Font/WindowServer APIs drift | Actively maintained fork or rewrite (SwiftUI min macOS 13) |
| Menu-bar icon missing | Crash before status item; hide-manager conflict; notch overflow | Floating overlay mode; graceful hide; avoid hide-manager fights |
| Unsigned forks blocked | Gatekeeper quarantine | Document `xattr -rd com.apple.quarantine` |
| Overlay UX | Lock/align/hit-region bugs | Explicit lock, bottom-center option, hit-test window |
