# F4 — Electron / macOS Tray 图标不显示的原因与正确配方

## 1. macOS 菜单栏 Tray 的显示模型

macOS 上的 `Tray` 落在 **菜单栏 extras 区域**（右上角），不是 Dock、不是通知中心。系统对这里的要求比 Windows 托盘更严：

| 要求 | 说明 |
|------|------|
| Template Image | 黑色 + alpha 通道；系统按浅色/深色菜单栏自动反色 |
| 逻辑尺寸 | **16×16 pt**（72dpi） |
| Retina | **32×32 @2x（144dpi）** 作为同一文件名的 `@2x` 表示 |
| 文件名（若走路径） | 基名以 `Template` 结尾，如 `iconTemplate.png` + `iconTemplate@2x.png` |
| 创建时机 | 必须在 `app.whenReady()` 之后 `new Tray(...)` |
| 强引用 | `Tray` 实例必须挂在模块级变量上，否则被 GC 后图标消失 |

官方依据：
- https://www.electronjs.org/docs/latest/api/tray （macOS platform considerations）
- https://www.electronjs.org/docs/latest/api/native-image#template-image-macos
- https://www.electronjs.org/docs/latest/tutorial/tray

## 2. 常见失败原因（按出现频率）

### A. 未标记 Template Image（最常见“看不见”）

- 现象：浅色菜单栏正常，深色菜单栏上图标是黑的 → **像没显示**。
- 原因：`nativeImage` 默认是普通位图；只有 `image.setTemplateImage(true)` 或文件名 `*Template.png` 才会被 NSStatusItem 当模板处理。
- 修正：
  ```js
  const img = nativeImage.createFromBuffer(buf);
  img.setTemplateImage(true);          // 必须
  const tray = new Tray(img);
  ```

### B. 尺寸 / 密度不对

- 只有 16×16、无 `@2x` → Retina 上发糊，极端情况下系统缩放异常。
- 传入 256×256 大图再 `.resize({width:16})` 可以，但**不会自动生成 @2x 表示**；应显式：
  ```js
  img.addRepresentation({ scaleFactor: 1.0, width: 16, height: 16 });
  img.addRepresentation({ scaleFactor: 2.0, width: 32, height: 32 });
  ```
  或直接提供磁盘上的 `xxxTemplate.png` + `xxxTemplate@2x.png`。

### C. LSUIElement / Dock 行为混淆

| 运行方式 | Dock | 菜单栏 | 说明 |
|----------|------|--------|------|
| 打包 .app + `LSUIElement=true` | 无 | Tray 可见 | 标准 menu bar app |
| `electron .` 开发态（无 plist） | **有** | Tray 可见 | 用户以为“有 Dock 图标所以不是托盘应用” |
| 无 LSUIElement 且无 `app.dock.hide()` | 有 | Tray 可见 | 双入口，用户容易找不到托盘 |
| 菜单栏图标太多 | — | **被挤掉/折叠** | Sequoia 上更明显；用户侧问题，不是代码 bug |

正确做法（菜单栏常驻应用）：
1. 打包 plist 保留 `LSUIElement=true`。
2. 主进程在 ready 后补一刀（开发态也生效）：
   ```js
   if (process.platform === 'darwin') app.dock.hide();
   ```
3. **不要**再创建可见主窗口当“入口”；入口就是 Tray。

### D. 多实例抢一个托盘 / 抢端口

- 未调用 `app.requestSingleInstanceLock()` 时，第二次启动会再 `new Tray`：
  - 菜单栏出现两个相同图标；
  - 第二实例 `listen(8765)` 失败，状态错乱；
  - 退出一个实例可能把共享资源拆掉，另一个实例托盘变僵尸。
- 正确配方：
  ```js
  const gotLock = app.requestSingleInstanceLock();
  if (!gotLock) {
    app.quit();
  } else {
    app.on('second-instance', () => {
      // 聚焦设置窗 / 弹出托盘菜单
      if (settingsWin) { settingsWin.show(); settingsWin.focus(); }
    });
    app.whenReady().then(main);
  }
  ```

### E. 生命周期 / GC

- `new Tray` 未赋给模块级变量 → 立刻被回收，图标创建后消失。
- 在 `ready` 之前创建 → 抛错或静默失败。
- 只在 `will-quit` 里逻辑清理但未 `tray.destroy()` → 偶发残留图标（需重启 SystemUIServer）。

### F. setContextMenu 与 click 事件在 macOS 上互斥

- 官方：设置了 `setContextMenu` 后，`mouse-up` **不会**再发出；macOS 上左键通常直接弹菜单。
- 因此“左键 toggle 窗口 + 右键菜单”的常见写法在 macOS 上往往只表现为菜单，click handler 不触发。
- 可选方案：
  - 只用菜单（最稳）：菜单里放「显示/隐藏设置」「显示/隐藏歌词」；
  - 或不用 `setContextMenu`，在 `tray.on('click')` 里 `tray.popUpContextMenu(menu)`（自己控制左/右键）。

### G. Sequoia / Sonoma 已知干扰（非代码可完全规避）

- 菜单栏图标过多时系统会折叠，用户以为“没显示”——先让用户拖出控制中心/检查隐藏区。
- 睡眠唤醒后个别版本 NSStatusItem 重建异常；可监听 `powerMonitor` resume 后 `tray.setImage(...)` 强制刷新。
- 未签名 / 被 Gatekeeper 改动过的 app 偶发辅助功能与菜单栏权限提示。
- Electron 28–33 在部分 Sonoma 点版本有 tray 图标闪烁 issue；保持 Electron ≥33 并避免频繁 `setImage`。

## 3. 正确配方（可直接抄）

### 3.1 图标

- 提供纯黑 + alpha 的 PNG：
  - `resources/trayTemplate.png` — 16×16
  - `resources/trayTemplate@2x.png` — 32×32，144dpi
- 或程序化：单色位图 + `setTemplateImage(true)` + 1x/2x representation。

### 3.2 主进程骨架

```js
const { app, Tray, Menu, nativeImage } = require('electron');

const gotLock = app.requestSingleInstanceLock();
if (!gotLock) app.quit();

let tray = null;

function trayImage() {
  const img = nativeImage.createFromPath(
    path.join(__dirname, '../resources/trayTemplate.png')
  );
  // createFromPath 时若文件名以 Template 结尾，Electron 会自动当模板；
  // 再保险一次：
  img.setTemplateImage(true);
  return img;
}

app.whenReady().then(() => {
  if (process.platform === 'darwin' && app.dock) app.dock.hide();

  tray = new Tray(trayImage());
  tray.setToolTip('手机歌词镜像');
  tray.setContextMenu(Menu.buildFromTemplate([
    { label: '显示/隐藏歌词', click: toggleOverlay },
    { label: '设置…', click: openSettings },
    { type: 'separator' },
    { role: 'quit' },
  ]));
});

app.on('window-all-closed', (e) => {
  // 菜单栏应用：所有窗口关掉也不退出
});

app.on('before-quit', () => {
  if (tray) tray.destroy();
});
```

### 3.3 打包 plist

```xml
<key>LSUIElement</key>
<true/>
<key>NSHighResolutionCapable</key>
<true/>
```

### 3.4 验收清单

- [ ] 浅色 / 深色菜单栏都能看清图标（template 生效）
- [ ] Retina 下不糊（有 @2x）
- [ ] 开发态 `electron .` 后 Dock 无图标（`app.dock.hide()`）
- [ ] 连开两次 app，只有一个托盘、一个 8765
- [ ] 关掉所有窗口进程仍在
- [ ] 菜单栏图标被系统折叠时，有工具提示或 `tray.setTitle` 可辨识

## 5. Summary（3–5 行）

1. macOS Tray 必须是 **Template Image（黑+alpha）** 且 **16×16 + @2x(32)**，否则深色菜单栏“看不见”或 Retina 发糊。
2. 菜单栏常驻应用要同时做 **`LSUIElement`（打包）+ `app.dock.hide()`（运行时）**，并用 **`requestSingleInstanceLock`** 防止多实例抢托盘/抢端口。
3. `setContextMenu` 与 `tray.on('click')` 在 macOS 互斥，入口交互应收敛到菜单。
4. 本仓库 main.js 的核心缺陷是：图标未 `setTemplateImage`、无 dock.hide、无单实例锁、click+菜单冲突、启动即弹设置窗。
5. 按第 3 节配方改动即可在浅/深色菜单栏稳定显示。
